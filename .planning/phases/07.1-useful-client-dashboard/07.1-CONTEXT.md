# Phase 07.1: Useful client dashboard — Context

**Gathered:** 2026-11-22, from the user's answers after the research scan (07.1-RESEARCH-NOTES.md)

## Decisions (locked)

- **D-71-01 Sections for every client:**
  1. **At a glance:** 3 key numbers for this month (for example calls, direction requests and website visits). Each shows an arrow and the change since last month in plain words ("up 12% on last month"). The marketer chooses the labels per client.
  2. **Waiting on you**, for approvals and things needed from the client, plus **Done this month**, a list of the work delivered.
  3. **Coming up**, with the next check-in and the renewal date, plus **contact** buttons to call, email or book a chat.
- **D-71-02 No "note from Sam" section.** The user left it out.
- **D-71-03 Growth-only features**, shown to Local Basics clients as visible but locked, with an upgrade prompt:
  - a 6-month trend chart of the key numbers
  - the content calendar (posts planned for the next 2 weeks)
  - ad results (spend, clicks, results)
  - the monthly report archive (links)
- **D-71-04 Build the locking now, in 07.1.** Lock by the client's plan, enforced in the database: a Local Basics client must not be able to read Growth-only data even by calling the API directly (RLS or a separate table or columns keyed by plan). The locked card in the page is only the display. Phase 8 then only adds payments.
- **D-71-05 Data entry:** the marketer types the monthly numbers and lists in Supabase's table editor. No API integrations in this phase (Google Business Profile and ad-account sync is future work and needs server code and OAuth).

## Carried over from Phase 7 (still binding)

- RLS: a client reads only their own data, and signed-out callers get nothing. Clients still cannot write.
- Strict CSP (`script-src 'self'` plus the one inline hash), no new third-party origins. Any chart is drawn with inline SVG or CSS, with no chart CDN.
- Home and Contact load no auth code and stay within the page-weight budget, and open by double-click.
- "Sample content" tagging, with fictional data only, until the D-11 human security check passes.
- Every push needs a fresh user approval. main must not move during the build.
- Guards run with `caffeinate -dimsu sh tools/run-guards.sh`.

- The renewal date and contact details: whether they come per client or from site-wide placeholders.
- How the two test clients are seeded: A is Local Basics (sees the locked cards) and B is Growth (sees everything). Extend tools/auth-rls-test.js with a case proving A cannot read Growth-only data directly.
