# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation & Design System. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Requirements covered: FND-01 to FND-05. Tokens defined here are the single source of truth for Phases 2 to 5. Where this file conflicts with 01-CONTEXT.md, CONTEXT.md wins (decisions D-01 to D-14).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (plain HTML, one hand-written CSS file, vanilla JS; no React, no build step, so the shadcn gate does not apply) |
| Preset | not applicable |
| Component library | none (hand-written semantic HTML plus BEM-lite class names) |
| Icon library | none. Service icons are clean, uniform line icons (D-12): inline SVG, single 2px stroke weight, round caps/joins, `fill: none`, `stroke: currentColor`, 24x24 viewBox, colour `--color-ink`. Not hand-drawn doodles. Icons themselves are built in Phase 2 |
| Font | Display/headings: **Fraunces** (soft, warm serif). Body/UI: **Figtree** (friendly geometric sans). Exactly 2 families, no script font. Both SIL OFL, self-hosted WOFF2 |
| Theme | Light only (D-03). `color-scheme: light`, no dark mode |
| Palette | "Social network brights" (D-01): white, blue tint, navy band, social blue accent, coral pop |

### File structure (FND-01)

```
index.html
contact.html            (stub in Phase 1: shell + title only)
styleguide.html         (visible style-guide view, see below)
REPLACE-ME.md           (placeholder content list; photo URLs + credits, D-13)
css/styles.css          (single stylesheet; @font-face, :root tokens, base, accents, utilities)
js/                     (empty or .gitkeep; classic <script defer>, never type="module")
assets/fonts/           (WOFF2 files + OFL licence files)
```

- Pages, CSS, JS and fonts use relative paths only (`css/styles.css`, never `/css/...`). No `fetch()` of local files, no ES modules, no `@import` of remote CSS, no CDN links for CSS/JS/fonts. Must work by double-click over `file://` and from a subfolder on a static host.
- Photos are the one exception (D-13): royalty-free stock photos (Unsplash/Pexels licence) are hotlinked, not bundled, and will not show offline. Every `<img>` must carry `width` and `height` attributes (or a CSS `aspect-ratio`) so a missing image causes no layout shift, plus meaningful `alt` text, `loading="lazy"` below the fold, and a `--color-tint` background as the placeholder behind the image. Photo URLs and credits are listed in `REPLACE-ME.md`. No photos are required in Phase 1 itself; the style guide may show one sample.
- `styleguide.html` is linked only from the Phase 1 stub pages (footer-adjacent dev link) and is excluded from the final two-page site by Phase 5. It does not count as a third public page.

## Focal Point

Per page, the visual hierarchy is declared as follows:
1. **Primary focal point:** the Display headline in Fraunces, with the social-blue hero word and its coral hand-drawn underline ("Marketing for your [word]"). It is the largest type, the only place the underline appears, and the only blue text at display size.
2. **Secondary focal point:** the primary CTA button ("Let's talk", social-blue fill) directly below the headline.
3. Everything else (nav, services, squiggle dividers) stays quiet and neutral so these two read first. "Calm with pops" (D-02).

## Spacing Scale

Declared values (all multiples of 4, 7 steps), exposed as `--space-*` custom properties:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, underline offset |
| sm | 8px | Compact element spacing, label-to-input gap, button vertical padding |
| md | 16px | Default element spacing, card inner gaps, mobile page gutter |
| lg | 24px | Card padding, button horizontal padding, tablet page gutter |
| xl | 32px | Layout gaps between grid items, desktop page gutter |
| 2xl | 48px | Major block breaks inside a section |
| 3xl | 64px | Section vertical padding on mobile |

Composed (no new token): desktop section vertical padding at 1024px+ is `calc(var(--space-3xl) + var(--space-xl))` (96px, built from existing tokens). No `4xl` token exists.

Exceptions:
- Minimum interactive target height/width: 44px (QA-01), implemented as `min-block-size: 44px` / `min-inline-size: 44px`, not as a spacing token.
- Focus ring: 3px outline, 3px offset. Borders: 1px or 2px. These are not spacing tokens.
- Decorative dimensions (not spacing): the squiggle divider is 12px tall and the hand-drawn underline SVG is 12px tall. They are artwork sizes and may not be reused for layout.
- Layout: content max-width 1120px (`--container`), prose max-width 64ch (`--measure`). Page gutter: `--space-md` under 640px, `--space-lg` 640 to 1023px, `--space-xl` at 1024px+.
- Breakpoints (documented here so all phases agree): 640px, 1024px. Mobile-first `min-width` queries only. Must be fully usable at 320px.

Radius tokens (not spacing): `--radius-sm` 8px (inputs, buttons), `--radius-md` 16px (cards), `--radius-pill` 999px (tags, pill buttons). Shadows: one soft cool shadow, `--shadow-card: 0 2px 0 rgba(27,42,74,.06), 0 8px 24px rgba(27,42,74,.10)`.

## Typography

Exactly 4 sizes and 2 weights across the whole site.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 18px (1.125rem) | 400 | 1.5 | Figtree |
| Label | 14px (0.875rem) | 600 | 1.4 | Figtree (nav, buttons, form labels, captions, footer fine print). Buttons and nav links use 600 at 14px with letter-spacing 0.02em; form field text itself is Body 18px |
| Heading | 28px (1.75rem) | 600 | 1.2 | Fraunces (h2, h3, card titles) |
| Display | clamp(40px, 6.5vw + 8px, 72px) | 600 | 1.1 | Fraunces (h1 / hero headline only). Max ~72px on desktop (D-07) |

Declared weights: regular 400 and semibold 600. No italics, no other weights (do not ship italic or bold files). Display line-height 1.1 is the single permitted exception to the 1.2 heading recommendation, because the kinetic hero stacks short lines.

Rules:
- Body text never smaller than 18px on any breakpoint, which also keeps form input text at 16px+ and prevents iOS zoom.
- Hero word fit (D-07): at 320px the Display size resolves to 40px and the longest word, "restaurant", must render on one line inside the 288px content width (16px gutters) with no horizontal overflow. The hero word slot uses `white-space: nowrap`, and the executor verifies this at 320px with the real Fraunces file (expected width roughly 210 to 230px at 40px, a researcher estimate). If it does not fit, lower the Display clamp minimum in steps of 2px until it does; do not break the word.
- Fraunces optical-size axis fixed (opsz 72 for Display, 36 for Heading), SOFT axis 100, WONK 0. If a variable file is too heavy, ship static instances: Fraunces SemiBold only.
- Font files (budget: total fonts under 120KB): `Fraunces-SemiBold.woff2` (Latin subset, must include `é` for "café"), `Figtree-Regular.woff2`, `Figtree-SemiBold.woff2` (Latin subset). Variable Figtree is an acceptable single-file alternative if smaller.
- `font-display: swap` plus metric-matched fallbacks to prevent layout jump (FND-04): declare `@font-face` fallbacks `"Fraunces Fallback"` (src: local("Georgia"), `size-adjust: 104%`, `ascent-override: 92%`, `descent-override: 24%`, `line-gap-override: 0%`) and `"Figtree Fallback"` (src: local("Arial"), `size-adjust: 100%`, `ascent-override: 95%`, `descent-override: 25%`, `line-gap-override: 0%`). The executor must verify values against the real files and tune until no visible reflow on swap. Stack: `"Fraunces", "Fraunces Fallback", Georgia, serif` and `"Figtree", "Figtree Fallback", system-ui, sans-serif`. **As built (Phase 1, after review WR-02/WR-03):** final tuned values, a separate 600-weight `"Figtree Fallback"` face (Arial Bold), metric-compatible clones (Gelasio, Liberation Sans, Arimo) and best-effort `"Fraunces Fallback Android"` / `"Figtree Fallback Android"` faces live in `css/styles.css` and `01-SKELETON.md`; those are authoritative over the starting values above.
- `<link rel="preload" as="font" type="font/woff2" crossorigin>` for Fraunces SemiBold and Figtree Regular (the above-the-fold pair). Preload with `crossorigin` is harmless over `file://`; fonts load via relative `url()` in `@font-face`.
- Heading text uses `text-wrap: balance`; body uses `text-wrap: pretty`. Tokens: `--font-display`, `--font-body`, `--fs-body|label|heading|display`, `--lh-body: 1.5`, `--lh-heading: 1.2`, `--lh-display: 1.1`, `--fw-regular: 400`, `--fw-semibold: 600`.

## Color

Social network brights, "calm with pops" (D-01, D-02). Exposed as `--color-*` custom properties. Light theme only.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-bg` | `#FFFFFF` | Page background, most surfaces |
| Secondary (30%) | `--color-tint` | `#F1F5FF` | Cards, header, alternating section bands, form field background, image placeholder background |
| Dark band | `--color-navy` | `#1B2A4A` | Closing CTA band and footer background only (the one dark band style); text on it is `--color-bg` (white) or `--color-tint` |
| Text | `--color-ink` | `#1C1E21` | Body text and headings (near-black) |
| Text muted | `--color-ink-soft` | `#4A5568` | Captions, helper text, placeholders-as-hints (never lighter than this) |
| Accent (10%) | `--color-blue` | `#3B5BFD` | See reserved list below |
| Accent hover/pressed | `--color-blue-hover` | `#2A44D4` | Hover and active state of blue elements only |
| Pop (decorative) | `--color-coral` | `#FF6B6B` | Decorative graphics on light backgrounds; text only on navy. See rules below |
| Destructive / error | `--color-error` | `#C62828` | Form validation errors only (Phase 4); distinct from coral; no destructive actions exist in this site |
| Line | `--color-line` | `#C9D3EE` | 1px dividers, default squiggle stroke (decorative only, not relied on for meaning) |

60/30/10 split: white is the 60% dominant surface; blue tint is the 30% secondary (cards, header, bands, fields); the remaining 10% is accent, made up of social blue (CTAs, links, hero word, focus ring) plus sparing coral decoration. Navy is a single inverse band style for the closing CTA band and footer and stays within those two components.

Blue (accent) reserved for (explicit list, nothing else may use `--color-blue`):
1. Primary CTA button background ("Let's talk")
2. The hero cycling word text colour (D-04)
3. Inline text links in body copy (underlined) and the current-page nav indicator
4. Keyboard focus ring colour (`outline: 3px solid var(--color-blue)`; on navy backgrounds the ring is `--color-bg`)

Coral (pop) reserved for:
1. The single hand-drawn underline beneath the hero word (D-04, D-09)
2. The optional highlighted squiggle divider stroke (at most one per page; default squiggle is `--color-line`)
3. Coral text on the navy band only (for example one highlighted word in the closing CTA headline), at Display or Heading size
4. Small decorative shapes on any background (never carrying meaning, never text)

Coral rules (D-01a): coral on white is 2.78:1, so coral must never be used for text, icons, borders or any essential UI on white or blue-tint backgrounds. Coral is not used for buttons.

Not accent: icons (use `--color-ink`), card borders, headings, section headings, backgrounds of large areas.

| ink-soft on tint | 6.90:1 | 4.5:1 | pass |
| blue on white (hero word, links) | 5.12:1 | 4.5:1 | pass |
| blue on tint (links) | 4.69:1 | 4.5:1 | pass |
| white on blue (button label) | 5.12:1 | 4.5:1 | pass |
| white on blue-hover (button hover label) | 7.30:1 | 4.5:1 | pass |
| blue-hover on white (link hover) | 7.30:1 | 4.5:1 | pass |
| blue-hover on tint (link hover) | 6.69:1 | 4.5:1 | pass |
| white on navy (CTA band, footer text) | 14.22:1 | 4.5:1 | pass (AAA) |

## Handcrafted Accent Kit (FND-03)

Exactly 2 accent types, a hard cap (D-09, D-11; FND-03 is now "1 to 4 accent types"). Both are inline SVG or CSS, themed from tokens, `aria-hidden="true"` and `pointer-events: none`. There is no paper grain texture and no blob photo frame anywhere in the site. Tone is "subtle seasoning" (D-10): layout reads clean and professional first.

| # | Accent | Implementation | Usage rule |
|---|--------|----------------|-----------|
| 1 | Squiggle section divider | Inline SVG, repeating wavy path 12px tall (decorative size), stroke 3px, `--color-line` by default or `--color-coral` for the single highlighted variant; class `.divider-squiggle`, full container width; a `background-repeat: repeat-x` data-URI SVG is allowed | Between major sections, at most 2 per page |
| 2 | Hand-drawn underline | Inline SVG path (`viewBox 0 0 200 12`, uneven stroke, round caps, `stroke: var(--hero-underline-color)` (coral), stroke-width 4, `preserveAspectRatio="none"` so it stretches to word width). Class `.accent-underline` wraps the word in `position: relative` with the SVG absolutely positioned under the baseline | Reserved for the hero word only (Phase 3 cycling word; static first word "bakery" in the Phase 1 stub). Never on section headings, body text or any other element |

Rules:
- Handcrafted accents sit on top of a strictly clean grid (12-column CSS grid collapsing to 1 column; uniform spacing tokens). Wobble belongs to decoration, never to layout or text alignment.
- Rotation: no rotation on controls or text containers. Decorative accents are not rotated.
- No third accent type may be introduced in later phases. Service icons (Phase 2) are clean uniform line icons and content illustrations, not accents. Arrows, stars, grain and blob frames are not permitted.
- All accents static in Phase 1. If any are animated later (e.g. underline draw-in), it is gated by `prefers-reduced-motion: no-preference`.

## Interaction Contract (foundation level)

| Element | States |
|---------|--------|
| Primary button (`.btn`, `.btn--primary`) | Default: blue bg, white text, Label type, `min-block-size: 44px`, `padding-block: var(--space-sm)`, `padding-inline: var(--space-lg)`, radius pill, inline-flex with centred content. Hover: blue-hover bg. Active: blue-hover bg, `translateY(1px)`. Focus-visible: 3px blue outline, 3px offset (white outline on navy). Disabled: not used in Phase 1 |
| Secondary button (`.btn--ghost`) | Transparent bg, 2px ink border, ink text. Hover: tint bg. Same padding tokens, focus, size and radius as primary. On navy: 2px white border, white text, hover bg `rgba(255,255,255,.12)` |
| Text link | Blue, underlined (2px, offset `var(--space-xs)`). Hover: blue-hover. Focus-visible same ring as buttons |
| Form field (style only; built in Phase 4) | Tint background, 2px `--color-field-border` border (= `--color-ink-soft`, ≥3:1 non-text contrast per WCAG 1.4.11; updated after Phase 1 review WR-01), radius 8px, `min-block-size: 44px`, `padding-block: var(--space-sm)`, `padding-inline: var(--space-md)`, Body text. Focus: 2px blue border plus ring. Error: 2px error border and error text below |
| Images (hotlinked photos, D-13) | Explicit `width`/`height` or `aspect-ratio`, `max-inline-size: 100%`, `block-size: auto`, `object-fit: cover`, radius `--radius-md`, tint background as placeholder, descriptive `alt` (empty `alt=""` only if purely decorative) |
| Motion tokens | `--ease-out: cubic-bezier(.22,.8,.3,1)`, `--dur-fast: 150ms`, `--dur-base: 250ms`. Only colour/transform transitions on interactive states. All transitions collapse to `0.01ms` under `@media (prefers-reduced-motion: reduce)` |
| Skip link | Visually hidden `a.skip-link` ("Skip to main content") as first focusable element, becomes visible on focus (ink bg, white text, `var(--space-md)` padding). Include in the stub pages |
| Global | `:focus-visible` ring defined once in base CSS; never `outline: none` without a replacement. `scroll-behavior: smooth` only under `prefers-reduced-motion: no-preference`. `html { color-scheme: light; }` (no dark mode in v1) |

## Copywriting Contract

Foundation phase has little user-facing copy. Tone rules and the few strings that exist are locked here so later phases inherit them.

Tone: first-person, warm, neighbourly, plain-spoken. Contractions are fine. No agency jargon ("synergy", "leverage", "solutions"). Short sentences. Name the reader's world (bakery, gym, salon) rather than abstractions. Sentence case everywhere, no ALL CAPS, no exclamation marks in headings, at most one per page elsewhere.

| Element | Copy |
|---------|------|
| Primary CTA | Let's talk |
| Secondary CTA example | See how I help |
| Nav labels | Home, Contact |
| Skip link | Skip to main content |
| Footer prototype note | Prototype — sample content |
| Hero headline pattern | Marketing for your [word], word from the shared list: bakery, café, salon, gym, florist, shop, restaurant |
| Stub page h1 (index) | Marketing for your bakery (placeholder, "bakery" in blue with coral underline; kinetic cycling is Phase 3) |
| Stub page h1 (contact) | Let's talk (placeholder, replaced in Phase 4) |
| Empty state heading | not applicable (no data-driven views in this site) |
| Empty state body | not applicable |
| Error state (form, defined now for Phase 4 tone) | "That email doesn't look quite right. Check for a typo and try again." (pattern: what is wrong in plain words plus how to fix it; no blame, no codes) |
| Success state (tone reference for Phase 4) | "Thanks, that's lovely. This is a prototype, so nothing was actually sent." |
| Destructive confirmation | not applicable (no destructive actions in this site) |
| Tone sample, services intro | "Four ways I help local businesses get found, get remembered and get busy." |
| Tone sample, About | "Hi, I'm [Name]. I live here too, and I love helping neighbours grow their business." |
