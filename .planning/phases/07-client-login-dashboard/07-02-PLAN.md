  <name>Task 1: Browser test harness and the public, SDK and file:// groups</name>
  <files>tools/auth-browser-test.js</files>
  <action>
Create tools/auth-browser-test.js using the CDP plumbing pattern from tools/qa-browser-test.js (raw WebSocket, withPage, named groups, `FAIL` lines, exit 0 or 1, Chrome from CHROME_PATH or the default path, temp profile cleaned up). Usage is `node tools/auth-browser-test.js [groups]`. No arguments runs every group except `live`, `deployed` and `rollback`.

Harness behaviour for every HTTP group:
- Run tools/build-site.sh, then serve `_site/` from a local server that applies the `headers` array from vercel.json to each response, so the test sees what Vercel would send. If BASE_URL is set, skip the server and load from that address.
- If BASE_URL answers index.html with 401 or 403, or redirects to another host (a login-protected Vercel preview), print `NOT RUN: address is protected` and exit 2. That is not a pass, and the caller decides on the manual fallback.
- An injected new-document script records `securitypolicyviolation` events. Any violation, uncaught exception, or console error fails the page, whatever the group. Do not call Page.setBypassCSP.
- Stubbing support: CDP `Fetch.enable` on `*://*.supabase.co/*`, fulfilling with canned JSON, CORS headers and OPTIONS preflights, and recording each request (path, method, whether it had a body) so tests can assert what was sent and when.
- Output goes through one print function that throws on any value from tools/auth-env.js secretValues(). Exit 2 means could not run. Before implementation, groups report missing pages and files as FAIL with no crash or hang, and Chrome is always closed.

Groups in this task:
- `sdk`: on a page served from memory by the test server under the vercel.json headers, the vendored file gives a global `supabase.createClient`, and creating a client opens no network connection and no WebSocket (research A9).
- `public` (AUTH-07, D-09): load Home and Contact at 1280 and 375 with no stubbing. No request URL matches supabase, auth-, login.js, dashboard.js or set-password, no off-origin request, transfer under 500KB, localStorage untouched. Clicking "Client login" from both reaches login.html.
- `file-login`, `file-dashboard`, `file-setpass` (AUTH-07): open over file://. The "Sign-in only works on the live site" card shows with the hosted link, the form is hidden, there are no console errors or exceptions, and no request reaches supabase.co. Home and Contact still work over file://, including the Client login link.
