<interfaces>
**Research correction, verified while planning.** 07-RESEARCH.md says the site has "zero inline scripts" and proposes `script-src 'self'`. That is wrong: index.html has one inline script in its head (the `motion-pending` script), and tools/check-home.js requires it to stay inline and before the stylesheet. A spike served a real build under candidate policies in headless Chrome, with these results:

| Candidate | Result on Home |
|-----------|----------------|
| `script-src 'self'` (research) | Violation `script-src-elem` at index.html line 12. `motion-pending` was never applied. The page still looks fine at a glance, so this failure is quiet |
| `script-src 'self' 'sha256-qvivYhW+2mBvcheivW9LjQqEsx/8ko5H2KYGitb2C9o='` | No violations at 1280 and 375, `motion-pending` applied, GSAP running (162 elements with style attributes set by script), fonts and images load |
| Same, on Contact | No violations |

Style findings from that spike and from scanning the files:
- GSAP and main.js set styles through CSSOM (`el.style`, `style.cssText`, `setProperty`), which `style-src 'self'` does not block.
- ScrollTrigger has one `setAttribute("style","")` call, which is the kind of call the policy can block. It did not fire in the spike, and the `csp` group will catch it if it ever does.
- The SDK has no `eval`, no `new Function`, no created style element, and no `setAttribute("style"`.
- No page has inline `<style>` or `style=`.

So `style-src 'self'` stands without `unsafe-inline`. The hash above is current as of planning. Recompute it from the built file, do not copy it blindly.

Policy to use, with REF from js/auth-config.js:

```text
default-src 'self'; script-src 'self' 'sha256-<computed>'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self' https://REF.supabase.co; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

- **Scope**: Two public pages (Home, Contact), plus Login, Set password and Dashboard for invited clients — per user decision (D-13)
