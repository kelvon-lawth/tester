<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to Supabase REST | Publishable key is public, so every request is untrusted and only RLS and grants decide |
| user to chat | Chat is not a safe place for secrets |
| repo to public | Config values are published |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-15 | Information disclosure | client_dashboards read across clients | mitigate | RLS select-own with `auth.uid()`; proved by R1 to R5 live |
| T-07-16 | Information disclosure | signed-out access | mitigate | Revoke from anon and public, policy to authenticated only; proved by R6 and R7 |
| T-07-17 | Elevation of privilege | client writes to rows | mitigate | Select-only grant, no write policy; proved by R8 and R9 with re-reads |
| T-07-18 | Elevation of privilege | open sign-up | mitigate | Console toggle by the human; proved by S1 |
| T-07-19 | Elevation of privilege | policy trusting user-editable data | mitigate | No user_metadata in policies; `sql` group forbids it |
| T-07-20 | Information disclosure | secret key or password pasted in chat | mitigate | Instructions name only two public values; key shape check refuses and asks for rotation without repeating it |
| T-07-21 | Spoofing | weak passwords | mitigate | Minimum 10 set in the console; leaked-password check is Pro-only, accepted for a prototype with fictional data |
| T-07-22 | Denial of service | free project pausing | accept | D-14: accepted for the prototype, documented in 07-07 |
</threat_model>
