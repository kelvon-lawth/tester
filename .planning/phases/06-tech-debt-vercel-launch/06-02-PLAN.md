## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repo to Vercel | The Vercel GitHub App reads the repo and deploys on push |
| user-pasted address to shell | Text from chat is used in curl commands |
| local repo to GitHub | Pushes to main now publish to production automatically |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | Information disclosure | Live Vercel deployment | mitigate | Gate 1 probes real files as well as folders, and requires exactly 404, so a 401 or a folder-only 404 cannot pass as "not served" |
| T-06-09 | Denial of service | Pages removal ordering | mitigate | pages.yml deleted only after Gate 1 passes, and Pages disabled only after the redeploy is proven, so one site is always live (D-07) |
| T-06-10 | Tampering | Pasted URL in curl commands | mitigate | Must match the https vercel.app pattern before use, quoted, GET and HEAD only |
| T-06-11 | Elevation of privilege | Vercel GitHub App access | mitigate | Checkpoint steps grant "Only select repositories", just this repo |
| T-06-12 | Spoofing | Credentials in chat | mitigate | Checkpoints ask for the address only and say not to paste tokens; the auth-gate rule never requests one (earlier tokens were pasted in chat) |
| T-06-13 | Information disclosure | Missing security headers on the live site | accept | Out of scope per CONTEXT; a static prototype with made-up content, no accounts and a form that sends nothing |
| T-06-14 | Spoofing | Long-lived old Pages address | accept | Unpublished in Task 3 and confirmed 404 in Task 4; a residual GitHub environment record exposes no content |

No package installs in this plan, so no supply-chain entry applies. No high-severity threat is left open.
</threat_model>
